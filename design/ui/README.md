# シロアリボージョ UI/UX の方針書(案)

Unity 版の画面(陣営選択・対戦・結果の3画面)を作り直すための方針です。HTML の試作(`design/ui/mock/`)で配置・操作の流れ・演出を確かめてもらい、omen の OK をもらってから Unity に移します。

- 対象は今ある3画面だけです。画面は増やしません(コイントス・拡大表示・選択シート・ログは、対戦画面の上に重ねて出すものです)
- 縦画面専用、参照解像度 1080×1920。この文書と試作の座標・大きさは、すべて 1080×1920 の px です(Unity の CanvasScaler の値と同じ)
- ゲームの文言・カードの効果文は仕様(`Assets/Data/cards.json`・`docs/spec/`)のまま使います。画面の案内文など、仕様にない UI の文言は「仮:」として下の 8 にまとめました
- ルールの判定は書いていません。試作の「使えるかどうか」「効果」は見た目を動かすための簡易版です。Unity では `Engine.HandOptions` などの Core の API を使います

## 試作の開き方

- ファイル:`design/ui/mock/index.html`(worktree では `/Users/a.nakashima/shiroari-bojo-unity-ui/design/ui/mock/index.html`)をブラウザで開きます。サーバーは不要です
- 9:16 の枠がブラウザの中央に出ます。マウスのクリックとドラッグで操作できます(スマホのタッチでも動きます)
- 絵は `Assets/Art/Cards/Illustrations/*.png` と `Assets/Art/Cards/back_common.png` を相対パスで読んでいます(コピーしていません)
- カードの文言は `mock/data.js` にあります。`Assets/Data/cards.json` から「没」以外を抜き出したもので、文言は変えていません。cards.json が変わったら、この文書の末尾「data.js の作り直し」で作り直します

### デバッグ用の帯(枠の外、画面の一番上)

| ボタン | すること |
|---|---|
| 陣営選択 / 対戦(防除)/ 対戦(シロアリ) | 画面を切り替える。対戦はコイントスと初期手札の配りから始まる |
| 途中の盤面 | 7ターン目くらいの盤面(侵食・バリア・ベイト・羽アリ・完全侵食あり)で、自分の手番から始める |
| 結果(勝ち) | 結果画面を出す |
| ドロー2枚 | 山札から2枚引く演出 |

## 1. 参考にしたこと・オリジナルにしたこと

受託のゲームなので、TCG ポケット(ポケモンカードゲーム ポケット)は「配置・操作の流れ・演出の気持ちよさ」だけを参考にしました。ロゴ・絵・部品の形・配色・アイコン・効果音などの見た目は使いません。

### 参考にしたこと(考え方だけ)

| 項目 | 取り入れた考え方 |
|---|---|
| 対面の配置 | 相手の領域を上、自分の手札を下に置き、真ん中に場を置く。目線が上から下へ流れる |
| 手札の扱い | 手札は画面の下で扇形に重ねて並べる。タップで拡大して読む、上に引き上げる(ドラッグ)と使う |
| 使えるものを光らせる | 今使えるカードと、置ける場所を光らせ、それ以外を暗くする。迷わせない |
| 手番の区切り | 手番の切り替えを画面を横切るバナーで知らせる。短く出して、すぐ操作に戻す |
| 相手の行動の見せ方 | 相手が出したカードを一度中央で大きく見せてから場に置く。何が起きたかを目で追える |
| ログは控えめ | 常時のログ欄はやめ、最新の1行を短く出し、全文は必要なときに開く |
| テンポ | 1つの演出は 0.15〜0.35 秒を基本にし、待たせない。大事な場面(完全侵食・勝敗)だけ長く見せる |
| 押し心地 | ボタンは押すと沈み、離すと少し跳ねて戻る |
| 選択の割り込み | 選ぶ操作(予知など)は下からシートを出し、カードの絵そのものをタップして選ぶ |

### オリジナルにしたこと

| 項目 | 内容 |
|---|---|
| 色とトーン | カードの「B ポップ」(`design/cards/frames/B_pop.css`)に合わせた、温かい木と紙の色。クリーム色の縁+濃い外リング+下への影、という B ポップの縁取りをボタン・パネル・バッジにも使う |
| 場の形 | 8つのポイントを「家の断面図」に並べる(屋根の下に上部 → 水回り → 乾燥箇所、地面の上に屋外)。ポイントの見出しの色は場所の種類(水回り・乾燥箇所・上部・枯れ木)の色 |
| 侵食の見せ方 | ポイントごとに「必要枚数のマス」を並べ、置かれたシロアリを種類の色+カースト(職・兵・羽・女王)で埋める。兵アリの「盾」、羽アリの「↑」を小さく添える |
| 勝ち筋の帯 | 両陣営の勝ち筋(完全侵食 x/5 と シロアリ山札の残り)を1本の帯に並べ、常に見えるようにする。家の形のマスで完全侵食を数える |
| 行動力 | 黄色い丸(カードのコストの丸と同じ色)を3つ並べ、使うとはじけて消える |
| 文字 | 丸ゴシック。見出しは「クリームの文字+濃い縁取り」 |
| 勝敗の演出 | 勝ち:黄色の光の放射と紙吹雪。負け:文字が上から落ちて弾み、盤面が灰色になる |
| 結果画面 | 家のエンブレム(守った/かじられた)+成績の表 |

### 拡大表示(今の CardDetail。対戦画面の上に重ねる)

PR #8 からの持ち越し(拡大カードがポイントとメッセージ欄を隠す)への答えです。

- **位置と大きさ**:B ポップの枠をほぼ等倍(630×880 → **628×877**、倍率 0.997)で、**画面の中央上寄り(左上 226,250)**に出す。上に札(ひとこと)、下に「もどす」「使う/場所を選ぶ」ボタン(y=1150)と「カードを上に引き上げても使えます」
- **何を隠すか**:拡大表示は「読むための一時的な画面」と割り切り、全体を暗い幕で覆う(タップは下に通さない。幕のタップで閉じる)。そのかわり、**盤面を見ながら選ぶ操作(対象のポイント選び)は、拡大を閉じた状態で行う**。「場所を選ぶ」を押すと拡大が手札へ縮んで戻り、盤面がすべて見える状態で、光ったポイントを選ぶ
- 対象を選ぶあいだの選んだカードは、手札の中で少し持ち上げて金色の縁を付ける
- ドラッグで使うときも、引っぱっているカードは 0.8 倍に縮めて、盤面を隠しにくくする

### 効果文・使えない理由・操作の案内をどこに出すか

PR #8 で、拡大中はメッセージ欄から効果文の行を外していた点への答えです。

| 情報 | 出す場所 |
|---|---|
| 効果文 | ①拡大表示のカードの中(B ポップの効果文の箱。「仮:」を含めて cards.json の文言のまま。画面側で書き換えない=決定)。②対象を選んでいる間・ドラッグ中は、案内の帯の2行目(最大2行。最長 60 字が2行に収まることを確認) |
| 使えない理由 | ①拡大表示の上の札(赤)。②使えないカードを引き上げようとしたとき、カードが震えて、速報の行に赤で出す。手札では暗くするだけにする(扇形で重なるため、カードの上に文字を載せない) |
| 操作の案内 | ①案内の帯の1行目(「カードを選んでください(行動力 残り3)」「光っているポイントを選んでください」)。②拡大表示の上の札(金色。場所のいるカードのとき)。③手番の最初は、帯の2行目に操作のヒント |
| カード名・コスト・区分 | 対象を選んでいる間は、案内の帯の1行目の頭(今の MessageBox と同じ「名前 コスト1 ・ 駆除」) |

## 3. 操作の流れ

### 対戦の始まり

1. 陣営を選ぶ → 対戦画面へ(フェード)
2. コイントス(コインが回って陣営の色で止まる)→ バナー「〇〇が先攻」(小さく「コイントスの結果」)。ログの文は `GameStarted` のまま
3. 初期手札を配る(自分は山札から手札へ1枚ずつ飛んで表に返る。相手は裏のまま上へ)
4. 先攻の手番へ

### 自分の手番

```
手番の始まり
 ├ バナー「あなたのターン」
 ├ 手番の始まりの効果(ベイト発動・バリアが切れる・羽アリが女王アリに など)を順に見せる
 ├ 行動力の丸が3つ、順にふくらんで点く
 └ 使えるカードが光る
カードを使う(何度でも)
 ├ A. タップ → 拡大表示
 │    ├ 対象のないカード:「使う」または上に引き上げる → 中央で「発動!」→ 効果
 │    ├ 対象のあるカード:「場所を選ぶ」→ 拡大が閉じる → 光ったポイントをタップ → カードがポイントへ飛ぶ → 効果
 │    │                  (案内の帯の「やめる」、または同じカードのタップで取り消し)
 │    └ 使えないカード:上の札に理由。「使えません」(押せない)
 └ B. ドラッグ(上級者向けの近道)
      ├ 対象のないカード:手札の上の線(y<1250)より上で離す → 使う
      ├ 対象のあるカード:光ったポイントの上で離す → 使う
      └ それ以外の場所で離す → 手札へ跳ねて戻る(使えないカードは震えて理由を出す)
効果の途中で選択が割り込むとき
 ├ 予知 → シート「予知:山札の上3枚」→ 1枚選ぶ →(残りが2枚以上なら)シート「山札の下に置く順番」→ 確定 → 選んだカードが手札へ
 ├ 偵察 → 相手の裏向きの手札がめくれる → シート「偵察:相手の手札」→ とじる
 └ 妨害 → 相手の手札の1枚が震えて飛んでいく
ターン終了を押す
 ├ 1枚も使っていない(Engine.CanMulligan)→ シート「1枚も使いませんでした」
 │    ├ カードを選んで「捨てて1枚引く」→ 捨てて1枚引く
 │    └「捨てずにターン終了」
 ├ 補充:5枚になるまで引く(ドローの演出)
 ├ 手札が8枚以上(Phase.HandLimitDiscard)→ シート「手札が7枚を超えています」→ 捨てる枚数ぶん選ぶ →「捨ててターン終了」
 └ 相手の手番へ
```

- 選択シートが出ている間は、ほかの操作を受け付けない(シートの外をタップしても閉じない。予知・手札上限は必ず選ぶ)
- 完全侵食や勝敗が決まったら、その場で効果の演出 → 勝敗の演出 → 結果画面

### 相手(CPU)の手番

1. バナー「相手のターン」、相手の領域に「考え中…」、案内の帯は「相手のターンです。CPU が考えています…」、手札は光らない(触れない)
2. 手番の始まりの効果を見せる
3. CPU の1手ごとに:少し待つ → 相手の手札から1枚が持ち上がる → 中央へ飛んで表に返り、大きく見せる(読めるだけの間)→ 速報の行に「CPU:〇〇を使った → キッチン」→ 対象のポイントへ飛ぶ → 効果
4. ターン終了 → 相手の手札が補充される → バナー「あなたのターン」

### 対戦の終わり

1. 勝敗の演出(勝利・敗北・引き分け)→ 結果画面
2. 「同じ陣営でもう一度」→ 同じ陣営で対戦の始まり(コイントス)へ
3. 「陣営を変えて遊ぶ」→ 陣営選択の画面へ戻る → 陣営を選び直して対戦の始まりへ

### ルールと表示の分け方

- 使えるかどうか・理由・対象は `Engine.HandOptions` の `Usable`・`Reason`・`Targets`・`NeedsTarget` だけを見る。試作の `options()` は使わない(画面側に判定を書かない)。手詰まり防止は `Engine.CanMulligan`、行動の確定前は `Engine.IsLegal`
- 選択シートは `Phase.ForesightChoice`・`Phase.HandLimitDiscard` と `_state.ForesightCards`・`HandLimitDiscardCount` から出す(今の RenderForesight など)
- 演出は「状態の差」ではなく「新しく増えたログ(GameEvent)」から作る。`Engine.Apply` の前後で `_state.Log` の増えた分を取り、`GameEventType` ごとに上の表の演出を並べた Sequence を作り、再生し終えてから `Render()` で状態どおりに描き直す(演出の途中で状態と見た目がずれても、最後に必ずそろう)
- 相手に見せる文は `GameEvent.TextFor(人の陣営)`。CPU の手札の中身は、偵察の結果以外では出さない(相手の手札の扇は枚数だけ)
- CPU の1手は今の `StepCpu()` のまま。出したカードの ID は `GameEvent.CardId` から取る
- `cpuStepDelay` を 0 にしたとき(テスト用)は演出を飛ばす道を残す

### 作り方

- UI はシーン/プレハブとしてエディタで組む。C# は振る舞いだけ(扇形の並べ方・ドラッグ・演出の再生)にし、`new GameObject` で UI を作らない。飛んでいくカードの写しは、シーンに置いた「演出用カード」のプレハブを使い回す(プール)
- 扇形の並べ方は小さな C# の部品(例:`HandFanLayout`)で `anchoredPosition`・`localEulerAngles` を計算する。式は `mock/app.js` の `fanSlot()`(間隔 = min(210, (1040−240)/(枚数−1))、傾き = (i−中央)×min(3°, 18°/枚数)、下がり = (i−中央)²×4px、選んだカードは 80px 上へ・傾き0・1.08倍)
- ドラッグは HandCardView に `IBeginDragHandler`・`IDragHandler`・`IEndDragHandler` を付け、離した位置がどのポイントの矩形に入るかを `RectTransformUtility.RectangleContainsScreenPoint` で調べる
- 今の `confirmUntargetedCards`(オフ=タップで即使用)は、新しい流れ(タップ=拡大)では使わない。消すか、オンに固定する
- 書体:M PLUS Rounded 1c の TTF(Regular・Bold・ExtraBold)と `OFL.txt` を `Assets/Fonts/MPLUSRounded1c/` に置き、TMP の Font Asset Creator で SDF を新しく作る(日本語は使う文字が多いので Dynamic にするか、cards.json・UI の文言から文字セットを作る)。既存の NotoSansJP の SDF には手を入れず、エディタを閉じたあとの書き戻しは今までどおり `git checkout` で戻す
- DOTween を使う(決定)。まだプロジェクトに入っていない(`Packages/manifest.json` にない)ので、Asset Store の DOTween(無料版)を `Assets/Plugins/` に入れる作業が要る
- 縦画面のセーフエリア(`SafeArea.cs`)の内側に、相手の領域(上 250px)と手札(下)が入ることを、ノッチのある端末の比率で確かめる
- 光の脈打ちなどの往復の演出は、毎フレームの Layout の再計算を起こさないよう、色・拡大だけを動かす

### 容量(カードのイラスト)

- 今:イラスト22枚(21枚+裏面)は Max Size 1024(Default)、圧縮 High Quality。Android では約15MB の見込み(統括の見積)
- 新しい配置での最大の表示幅:**拡大表示の絵の窓が約 536×397px**(1080 幅の画面で。元の絵は 3:2 なので、窓いっぱいに切り抜いて表示すると、絵の幅は約 597px 分を使う)。ほかは、陣営選択の絵の窓 約 398×318px(絵の幅 約 477px 分)、CPU が出したカードの表示 約 333×247px(約 370px 分)、選択シートのカード 約 258×244px(約 366px 分)、手札 約 206×195px(約 293px 分)
  - 今の Unity の配置(拡大 約390px、手札 約130px)より大きくなる
- **Max Size 512(約4MB)で足りるか**:手札・選択シート・陣営選択・CPU の表示には足りる(最大でも約 477px 分)。拡大表示だけは、1080 幅の端末で約 1.17倍(597÷512)に引き伸ばすことになり、少しぼやける可能性がある(1440 幅の端末では約 1.55倍)
- **決定(2026-11-25)**:Max Size を **512** にする(約4MB)。Unity で、拡大表示の絵の見え方(1080 幅と、1440 幅に近い比率)を確かめる
- 512 でぼやけたときの次の手:
  - B. 1024 に戻し、Android の圧縮を ASTC 6×6 など粗めにして容量を下げる(ASTC 4×4 に比べて約 0.44倍)
  - C. 拡大表示の大きさを約 0.85倍(絵の窓 約 457px)まで下げ、512 に合わせる(その分、効果文の文字も小さくなる)
